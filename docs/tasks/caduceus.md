## 已冻结的产品规则

- 应用中文名为“双蛇杖”，英文内部标识暂用 `Caduceus`。
- 主菜单位置固定在“硬币决定器”之后、“提取部模拟”之前。
- 普通阶段共有九把武器；每次从本次尚未完成的武器中随机显示一把。
- 底部数字 1～9 表示本次进入后的完成顺序，不绑定武器编号；数字本体为白色，每完成一步就从1开始连续增加一个青色描边。
- 每把武器接受一种或多种基础动作；不同武器允许复用动作和音效。
- 六种应用专属基础动作是：横斩、竖斩、两个方向的斜斩、突刺、上挑。
- 两个斜斩的物理定义固定为：从左上向右下挥动，以及从右上向左下挥动；内部A/B名称只需稳定绑定两个方向，不要求用户记忆A/B。
- 每一种动作都必须接受两种握持朝向：屏幕朝向手心、屏幕朝向外侧。这是同一动作的机身翻面变体，不新增第二套业务动作枚举，也不要求IMU推断“掌心”本身。
- 只有侧键短按可以推进武器、推进“开始吧”和操作 Furioso；旋钮主按键短按不承担这些操作。
- 当前武器未完成时侧键短按无效；完成后侧键短按播放切换音效并切到剩余武器。
- 正确动作触发青色边框、对应武器音效和正确震动；错误动作触发红色边框和另一种震动，不播放对应武器音效，不改变数字状态。
- “第一次完成”的作用域是本次进入应用后、每把武器第一次完成；额外语音不跨退出保存。
- 当前随机武器第一次做对后允许继续重复触发所有相关动作；每次都播放武器音效、青框和正确震动，但只在第一次推进步骤并播放首次完成台词。首次完成台词必须等该次武器音效结束后再播放。
- 普通阶段所有状态均不保存；退出再进入时重新开始。
- 第九把武器完成后，侧键短按显示“开始吧”；再次侧键短按进入 `Furioso`。
- Furioso 共九个节拍，前八拍从九把普通武器独立随机且允许重复，最后一拍固定镰刀。
- Furioso 成功完成后暂时不增加特殊结算内容；长按退出。
- Furioso 失败时使用失败震动并显示特殊武器勺子；侧键确认后结束本次应用。
- 模式名称拼写固定为 `Furioso`。
- 普通武器固定编号按资源顺序并跳过特殊勺子：1斧、2锥、3大剑、4锤、5刺剑、6镰刀、7枪、8剑、9鞭；勺子只用于Furioso失败。
- 大剑和锤只接受竖斩；锥、刺剑和枪只接受突刺；镰刀、斧和鞭接受横斩/竖斩/两个斜斩；剑接受全部六种动作。
- 大剑音效只绑定大剑/锤，镰刀音效只绑定镰刀；其他武器每次进入应用时从`sword/sword2/sword3/whip`随机绑定一次，并在本次流程内保持稳定。
- `first`~`ninth`语音按本次完成顺序绑定，不按固定武器编号；三个`change_weapon`切换声每次推进时随机播放。
- Furioso前八拍随机分配九把普通武器，允许重复；第九拍固定镰刀。当前首版节奏窗口为可集中调节的保守参数，不视为实机定稿。

## 不得破坏的架构边界

- `SysMotion` 继续作为 LSM6DSL 唯一采样所有者，统一使用 104Hz、±16g、±2000dps；正常和采集固件不得使用不同量程。
- 双蛇杖增加独立 `SysGestureProfile::Caduceus`；六种动作只在本应用内识别，不进入全局 Default。
- 识别层只产生基础动作语义、强度、方向、采样时间及候选诊断元数据，不知道当前武器，不播放反馈，不绘制 UI。
- App 只根据武器配置表判断动作是否接受，不读取 IMU 原始值，不复制识别阈值。
- 只有被高置信度识别为六种基础动作之一的事件才可判错；普通晃动、模糊动作和被拒识的波形不能触发红框。
- `AppManager` 继续通过统一 `AppBase::onGesture()` 分发专属动作；不增加双蛇杖专用分发入口。
- 图片和音频由 SYS 资源域预热并持有；App 不直接打开 FATFS，也不持有文件路径。
- 音频继续通过 `AudioAssetId` 播放；复用音效时多个武器绑定同一个 ID，不重复加载 PCM。
- 正确、错误和 Furioso 失败震动通过 `sys_feedback` / `SysHaptic` 的业务语义封装；App 不写 TM6605 效果编号。
- 固定 UI 文本进入 `UIStrings`；绘制和动画进入 UI 层；App 只维护流程状态。
- 所有新代码写详细中文注释，新增或修改的串口信息使用中文；不确定的接口必须查声明、实现和调用点。

## 已批准的识别底座改造（当前最高优先级）

### 改造原因

- 当前BSP按LSM6DSL寄存器顺序返回X/Y/Z，`SysMotion`又把换算值原样写入含义模糊的`SysMotionSample::imu`；代码没有经过实机确认的“传感器坐标→机身/屏幕坐标”安装矩阵。
- 当前双蛇杖直接把原始`ay`解释为突刺方向，并用原始/累计`x/y/z`区分斩击。即使动作波形稳定，只要IMU安装轴、屏幕旋转和产品物理方向没有对齐，语义就会系统性错误。
- `MahonySolver`目前按固定104Hz步长积分，斩击主相位的累计角速度也没有乘真实`dt`。现有采集已经确认存在30～40ms空洞，因此不等间隔样本会污染姿态和主旋转轴。
- 六轴静止数据只能确定重力、俯仰和横滚，不能提供绕重力轴的绝对航向。双蛇杖不需要指南针航向；应使用“已标定的机身轴+每次动作开始姿态”建立局部动作坐标，而不是为不同握姿复制多套阈值。

### 目标分层与接口原则

1. **BSP保持传感器事实层**：继续负责I2C、寄存器、原始读数、量程换算和fresh状态，返回LSM6DSL自身坐标；不得在BSP内写横斩、突刺或App语义。
2. **SysMotion建立明确坐标契约**：仍是唯一采样所有者。长期明确区分诊断用原始整数、换算后的传感器坐标和安装矩阵转换后的统一机身坐标。迁移期间不得悄悄改变旧`.imu`含义，以免反转Default滚动、Karma或Sea；先新增明确接口/字段并逐个迁移，全部回归后再删除含糊旧接口。
3. **安装矩阵只由实测冻结**：统一机身轴的正方向必须在六面静态和三轴双方向旋转数据分析后写明。若数据证明只是轴交换/翻转，使用固定有符号置换；若存在不可忽略的安装偏角，再考虑一般旋转矩阵，不能预先猜测。
4. **SysPose使用真实时间**：把固定频率更新逐步升级为显式`dt`或时间戳驱动，并对断点、异常长间隔和恢复后的首帧作统一处理。姿态积分与动作角速度积分都必须按真实时间加权。
5. **增加可复用动作局部坐标工具**：在确认静止后冻结动作开始重力/姿态，把后续机身角速度、线性加速度和相对旋转转换到同一个起手坐标，统一提供去重力、主旋转轴、动作平面、相对角度、相位和完整度特征。该工具不认识武器、UI或反馈。
6. **连续姿态与动作局部姿态分离**：Sea等连续页面可以使用平滑连续姿态；双蛇杖每次动作使用独立局部起点。识别器重锚不得修改其他页面的全局姿态，也不得建立第二个IMU采样任务。
7. **分类语义保持在专属识别器**：改造后的`SysCaduceusRecognizer`仍只输出六种基础动作、强度、方向和时间；App继续只做武器允许动作判断。模糊/拒识波形仍不进入App。

### 数据采集与落地顺序

1. 用现有标签1～6各采至少两次稳定会话：屏幕正/反面、机身左/右侧、机身顶/底朝下；取静止中段均值，确认三轴映射、符号、模长、零偏和交叉轴残量。
2. 隔离采集固件已经增加标签20～25：绕机身左右轴时顶部/底部朝人、绕机身顶底轴时左侧/右侧朝人，以及正视屏幕顺/逆时针旋转。每组做约5～10次清晰单轴旋转，用来验证陀螺仪轴、符号和交叉耦合；这些标签只描述物理动作，不预设原始LSM6DSL轴。
3. 把确认后的机身轴定义、安装矩阵、正旋转约定和验证数据写入本账本及项目Skill动作工作流；原始CSV继续保留，不能只保存结论。
4. 实现不破坏旧消费者的`SysMotion`机身坐标输出，再把`SysPose`和动作积分改为真实`dt`；为时间断点补离线回归。
5. 建立动作局部坐标工具，并同步改造C++识别器与Python回放。先把已有六类/负样本CSV转换重放，只有转换后仍暴露真实重叠的类别才补采动作，不无条件废弃已有数据。
6. 第一批只迁移双蛇杖。实机重新验证轻/中/重、两个横斩方向、两种斜向、突刺/上挑和全部负样本后，再逐个评估Default、Karma和Sea是否迁移到机身坐标；每迁移一个消费者都保留行为回归。
7. 所有消费者迁移并通过实机回归后，才删除旧的含糊`.imu`接口。九武器资源、反馈和Furioso继续等待识别底座通过验收。

## 脱线 IMU 采集方案

脱线记录已经在原隔离测试体系中实现，不建立第二套传感器驱动：

1. 仍由 `SysMotion` 采样，不直接读取 BSP I2C。
2. 采集固件启动后由 ESP 独占挂载 FATFS，把 CSV 写入 `/Resources/_capture/imu/`。
3. 使用屏幕显示当前动作、倒计时、记录状态、重复次数和写入结果。
4. 使用旋钮选择动作标签；使用主按键启动一次记录；开始前留出倒计时，让用户松开按键并摆好姿势。
5. 每次记录保存为 `labelNN_sessionNNNN.csv`；CSV 前十一列保持旧契约，末尾增加会话号和三个 fresh 标志。
6. 完整会话先缓存在384KiB PSRAM，动作期间不刷新屏幕、不写FAT；结束后显示保存页并统一 write/flush/close。
7. 采集结束后关机或重启，进入独占 MSC 模式，再从电脑复制文件；ESP 写 FAT 与 PC MSC 绝不能同时进行。
8. 脱线模式验证稳定后再采六种动作，避免先采出无法区分重复次数或存在丢帧的数据。

采集数据至少覆盖：每类轻/中/重各 10～20 次、允许的不同握姿、其他五类动作互为负样本，以及菜单摇动、换武器、业力敲击、按键、普通手持、拿起放下、行走和近似未完成动作。

## 2026-08-02 固定入口人体坐标漂移诊断

- 新增纯SYS数学模块`SysHumanFrame::Tracker`和系统设置页“坐标漂移测试”。App只复制`SysMotion_GetLatest()`中的`body_imu`，不读取LSM6DSL、不消费`SysMotion`待处理环、不打开文件；`SysMotion`仍是唯一采样者，正式`SysCaduceusCore`、六分类阈值、事件和双蛇杖业务状态均未修改。
- 固定入口沿用当前用户摆放：屏幕朝上、底边朝向自己；校准至少等待1秒，并要求角速度小于120dps、加速度模长位于`1g±0.25g`、连续静止至少70ms，最近32帧fresh数据估计重力和三轴陀螺仪零偏。由此定义HumanX=BodyX向人体右、HumanY=BodyY向人体前、HumanZ向上。六轴IMU只能验证屏幕大致朝上，不能验证底边朝人或观测绕重力轴的绝对航向。

- 去重力过程使用Mahony机身到入口四元数把Body加速度旋转到Human坐标，再减入口重力；同时显示辅助与纯陀螺仪两份XYZ、当前残差、RMS和最大值。姿态页显示两通道yaw/pitch/roll、入口零偏和纯陀螺仪航向漂移速率；统计页记录yaw首次达到1°/3°/5°/10°、纯陀螺仪合成倾斜首次达到1°/3°/5°，以及丢序、超过30ms间隔、stale加速度和断点数量。
